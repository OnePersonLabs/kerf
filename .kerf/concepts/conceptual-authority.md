# Meaning directs implementation

An authored concept explains intended behavior and its reasons independently of
where or whether code exists. Imports and tests supply evidence; they cannot
silently decide what a project should mean.

Codex may revise meaning under the user's existing authorization. A clear change
request is sufficient. Ask only when intent remains materially conflicting or
unclear. There is no separate acceptance ledger.

A title is presentation; a descriptive key identifies the concept across edits.
Relationships are authored conceptual claims, not conclusions drawn from filenames.

The musical example can create a classifier from meaning alone, then replace that
classifier without changing why playback must stay outside player evidence.

Open question: how much meaning is worth retaining in actual projects? Keep what
helps future decisions. Do not require a conceptual record for every code symbol.
